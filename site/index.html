DEEPSEEK HARNESS · CADENCE VIRTUOSO

dsh-virtuoso-bridge

Your agent's hands inside Virtuoso.

The DeepSeek Harness plugin around Virtuoso Bridge, the upstream tool that connects an agent to a Cadence Virtuoso CIW. This plugin deploys that bridge in one click — isolated venv, pinned source, CIW daemon setup — and keeps it live across sessions: conversations, forks and subagents share one managed tunnel and daemon, and automatic-session discovery picks the right instance or workdir.

Start with an install → See the agent tools

WHAT THE PLUGIN OWNS

The bridge outlives
the conversation.

Runtimes, tunnels, daemons and the isolated Python environment are managed by the Host half of the plugin. Every conversation, fork and subagent in the profile talks to the same live bridge.

01

Managed runtimes

Start, stop, restart and test connections. State survives conversation changes and is projected into the right-sidebar panel.

02

Whole Python API

Describe and call any public virtuoso-bridge target — schematic, layout, library, Maestro, dialogs, Spectre — without plugin wrappers.

03

Batched scripts

Run Python in a fresh venv process with the connected client, jobs, progress and cancellation. A bad batch cannot break the connection.

04

CIW awareness

Warnings and *Error* lines printed during a call come back with the result, so a quiet failure is not silent.

FOUR TOOLS, ONE BRIDGE

Everything the agent
needs, nothing it must guess.

The tools are registered on the Host and are available in every conversation of the profile. Long work becomes a job; a big answer becomes a file the agent can grep.

RUNTIME

Connect and observe

Status, start, stop, restart, ping, instance discovery, daemon deployment, host-key trust and connection edits.

virtuoso_bridge_runtime action=status
virtuoso_bridge_runtime action=start connection=lab
API

Describe, then call

Three zoom levels over the installed bridge: target index, one target's methods, one method's full documentation. Then invoke it.

virtuoso_bridge_api action=describe target=client.layout
virtuoso_bridge_api action=call target=client method=execute_skill
SCRIPT

Batch real Python

Inline code or a workspace file, one job per run, with connect(), emit() and a persisted result.

client = connect()
result = {"windows": client.schematic.list_windows()}
SETUP

Repair the venv

Install, update, diagnose, switch source mode and clear caches, with the install log kept in the configuration page.

virtuoso_bridge_setup action=status
virtuoso_bridge_setup action=diagnose

THE AGENTIC LOOP

Read state.
Then act.

The plugin is deliberately not another runner, job store, dialog manager or scheduler. It exposes the bridge, and the bridge owns the logic.

STEP 01

Read the runtime

One status call reports setup, tunnel, daemon, instance, attached agents and running actions.

STEP 02

Describe the API

The installed bridge is the source of truth; describe it before calling instead of guessing a signature.

STEP 03

Batch the work

One larger script beats many round trips. Point path at a file you can edit and rerun.

STEP 04

Read the CIW

The returned block carries warnings and errors from the shared transcript — read it before guessing why nothing happened.

FIRST RUN

Install the bundle.
Create a venv.
Pick a daemon.

The npm package carries the pinned bridge source, so an install needs neither git nor the submodule checkout. Python 3.9+ and OpenSSH are the only local prerequisites worth checking first.

  1. 01Install the bundle @nekomona/dsh-virtuoso-bridge through the plugin manager.
  2. 02Open dsh-virtuoso-bridge in the left panel list and press Install to create the isolated venv.
  3. 03Add a connection and start it, or deploy the daemon setup first when the CIW is idle.
  4. 04Run the printed load("...") line in the CIW; the health poll flips the runtime to running.
